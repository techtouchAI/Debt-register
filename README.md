# 1) تحليل المشروع

## 1.1 الفكرة والمشكلة التي يحلّها

كثير من المكاتب والمتاجر الصغيرة تدير اليوم عملها بدفتر ورقي أو ببرنامج محاسبي متصل بالإنترنت يحتاج اشتراكاً وسيرفراً واتصالاً مستمراً. هذا المشروع يقدّم البديل الكامل:

- **دفتر إلكتروني بديل للورق**: يُسجِّل الفواتير (نقدي/آجل)، التسديدات، المخزون، وأرصدة الزبائن، ويطبع مستندات رسمية (فاتورة، وصل قبض، كشف حساب).
- **مطابقة حسابية موثوقة**: الأرصدة تُحسب من حركات دفتر الذمم لا من حقول قابلة للتعديل اليدوي، وكل عملية مالية تتم داخل معاملة واحدة (تنجح كلياً أو تفشل كلياً).
- **بيانات لا تغادر الجهاز**: لا API ولا تحليلات ولا تسجيل دخول سحابي — مناسب لبيئة بلا إنترنت أو ضعيفة الشبكة، ويحمي خصوصية بيانات العملاء.
- **جاهز للاستخدام من أول تشغيل**: معالج تشغيل أول يطلب اسم المكتب وهاتفه وعملته وعنوانه وتذييل فاتورته (تظهر في ترويسة كل مستند)، ثم يعمل فوراً.

## 1.2 الجمهور المستهدف

| الجهة | الاستخدام |
|---|---|
| صاحب مكتب / متجر | متابعة الأرباح والمخزون وديون السوق من لوحة تحكم واحدة |
| موظف مبيعات | إصدار الفواتير واستلام التسديدات فقط، بصلاحيات محسوبة |
| أنشطة بلا إنترنت مستقر | عمل كامل محلياً على الهاتف أو الحاسبة |

## 1.3 مبادئ التصميم (قرارات جوهرية)

1. **الدفتر هو مصدر الحقيقة (Ledger-first)** — رصيد الزبون يُحسب بجمع حركات جدول `customer_ledger` (فاتورة +، تسديد −)، وليس من حقل `remaining` على الفاتورة. هذا يمنع أي تعارض بين الشاشات والتقارير، ويجعل كشف الحساب قابلاً للتدقيق حركةً حركة.
2. **المعاملات الذرية (Atomic Transactions)** — حفظ الفاتورة = بنود + خصم مخزون + قيد ذمة + رقم مستند + دفعة مقدمة، كلها في `db.transaction`. أي فشل في المنتصف يرجع كل شيء، فلا تبقى «فاتورة بلا بنود» أو «مخزون غير متزن».
3. **دفاع ثنائي عن الصلاحيات** — مصفوفة صلاحيات واحدة (`permissions.ts`) تحكم القائمة والمسارات وزر الواجهة، **و** تتحقق مرة أخرى داخل طبقة البيانات نفسها (`assertPermission`) فلا يمكن تنفيذ عملية ممنوعة حتى بالوصول المباشر.
4. **لا فقدان للأرقام الرسمية** — أرقام الفواتير والوصولات تُولَّد بمنطق «أعلى رقم مستخدم ∪ علامة high-water» في جدول `meta`، فلا يُعاد استخدام رقم مستند محذوف ما زالت نسخته الورقية عند الزبون.
5. **المال يُقرَّب دائماً لخانتين** — كل مبلغ يمرّ عبر `roundMoney` (تقريب عشري آمن) لمنع تراكم فروق الفاصلة العائمة في الأرصدة والتقارير.
6. **العربية أولاً وبالكامل** — لا نص إنجليزي يظهر للمستخدم (حتى أسماء الملفات ورسائل الأخطاء وأنواع المدفوعات)، مع خط Cairo مدمج داخل التطبيق يعمل دون إنترنت، واختبار آلي يمنع تسرّب أي كلمة إنجليزية.
7. **التدهور اللطيف** — أي فشل في الطباعة أو الإشعارات أو الحفظ الخارجي لا يُسقط التطبيق؛ يُعرض تنبيه عربي واضح وتُسجَّل الحالة، وتبقى البيانات في قاعدة البيانات سليمة.

```

┌───────────────────────────▼─────────────────────────────────┐
```

**تسلسل الإقلاع**: فحص توفر التخزين → فتح قاعدة البيانات وترقياتها (v1→v3) → صيانة البدء (مصالحة الأرصدة، تحويل الرموز لبصمات، قص السجلات) → تشغيل النسخ التلقائي → تهيئة الإشعارات → التحقق من اكتمال بيانات المكتب (معالج أول تشغيل أو دخول تلقائي) → شاشة الدخول إن كان القفل مفعّلاً → الواجهة.

# 2) ميزات التطبيق

## 🏢 الإعدادات وبيانات المكتب
- بيانات المكتب: الاسم، الهاتف، العملة، العنوان، تذييل الفاتورة، والشعار (Logo) — تظهر تلقائياً في ترويسة كل فاتورة ووصل وكشف حساب.
- معالج تشغيل أول إلزامي: لا يبدأ النظام قبل استكمال بيانات الترويسة، ولا يمكن تخطيه بحفظ جزئي.
- العملة من قائمة جاهزة: دينار عراقي (افتراضي)، دولار، ريال سعودي، جنيه مصري، دينار أردني.
- اسم المكتب يُحفظ كاملاً حتى 150 حرفاً بلا اقتطاع، ويتغيّر حجم خطّه تلقائياً ليبقى داخل الترويسة.
- الوضع الليلي/النهاري بتبديل فوري وحفظ التفضيل (ينتقل مع النسخة الاحتياطية).
- حدّ نفاد عام افتراضي (مع إمكانية تحديد حدّ أدنى لكل مادة على حدة)، وتفعيل النسخ التلقائي ومدّته.
- مسودات الإعدادات غير المحفوظة تُحفظ محلياً فلا تضيع عند الخروج أو إعادة تحميل التطبيق.
- صفحة «معلومات المطور» بقنوات التواصل الرسمية (يوتيوب/تيليغرام) تُفتح في المتصفح.

## 👥 المستخدمون والصلاحيات والدخول (محلي 100%)
- دوران: **مدير** (كل الصلاحيات) و**موظف مبيعات** (بيع + قبض + إضافة زبائن + إطلاع فقط).
- رمز دخول (PIN) اختياري لكل مستخدم: تفعيل/تغيير/تعطيل + زر قفل لتبديل المستخدم.
- الرموز تُخزَّن كبصمة **SHA-256 مع ملح**، ولا تُعرض أبداً، مع إيقاف مؤقت 30 ثانية بعد 5 محاولات خاطئة (يبقى بعد إعادة التشغيل).
- **رمز استرداد** من 12 رقماً يعيد تعيين رمز المدير عند نسيانه — يُستخدم مرة واحدة ثم يُبطَل.
- تثبيت جديد: مدير واحد بلا رمز معروف، والدخول تلقائي حتى يفعّل المدير القفل بنفسه.
- القائمة والمسارات والأزرار كلها محروسة بمصفوفة صلاحيات واحدة، وأي محاولة من طبقة البيانات مرفوضة برسالة عربية.
- **سجل نشاطات** يسجّل الإجراء ومن نفّذه ومتى، مع بطاقة عرض وصفّ.

## 📦 إدارة المخزن (قاعدة بيانات المواد)
- إضافة مادة سريعة: الاسم، الوحدة، الكمية في نموذج واحد (مع تكلفة افتتاحية تُسجَّل كحركة مخزون).
- تفاصيل المادة: الكمية، سعر البيع، **متوسط التكلفة المرجّح** المحسوب من حركات المخزون، آخر تكلفة إدخال.
- إدخال مخزون أو تسوية يدوية مؤرخة بتكلفة وحدة وملاحظة، مع تحديث ذري للكمية ومتوسط التكلفة.
- **منع المخزون السالب** في كل مسارات الصرف والتعديل.
- شارات حالة المخزون: طبيعي / منخفض / نافد بلون مميز، مع تنبيه عند النفاد.
- فئات ووحدات متعددة (قطعة، كيس، لتر، كغم...)، وباركود اختياري، وحدّ أدنى لكل مادة.
- حساب قيمة المخزون والأرباح المحتملة، وحماية من حذف مادة مرتبطة بفواتير.

## 👤 إدارة العملاء (سجل الزبائن)
- بطاقة الزبون: الاسم الرباعي، الهاتف، العنوان، الملاحظات.
- **عرض الدين الحالي بجانب كل زبون** مباشرة وترتيبه.
- بحث عربي ذكي بالاسم أو الهاتف أو العنوان (مع دعم الأرقام العربية-الهندية).
- كشف حساب تفصيلي زمني لكل زبون بعرض وطباعة وحفظ كمستند.
- حماية: لا يمكن حذف زبون عليه دين — تُعرض رسالة تشرح السبب.

## 🧾 المبيعات والفواتير (قلب التطبيق)
- إنشاء فاتورة **نقدي أو آجل**، وتحديد الزبون من القاعدة أو زبون عابر للنقدي.
- سلة بيع ذكية: حقل بحث للمادة، السعر ينزل تلقائياً، إدخال الكمية → حساب فوري للصف، مع تحقق من الكمية المتوفرة.
- حساب الإجمالي والخصم (مقيّد ≤ الإجمالي) والمدفوع والدفعة المقدمة والمتبقي.
- **الرصيد السابق** يُعرض في الفاتورة الآجلة كلقطة تاريخية ثابتة مطابقة للنسخة الورقية.
- خصم المخزون تلقائياً عند الحفظ، وإرجاع الكميات عند التعديل/الحذف داخل معاملة واحدة.
- عرض الفاتورة: معاينة A4، طباعة، حفظ PDF باسم عربي (للإرسال على واتساب)، تعديل وحذف (للمدير).
- أرقام فواتير عربية بصيغة `ف-YYYYMM-NNNN` لا تتكرر ولا تُعاد، والأرقام القديمة (INV) تُعرض بالبادئة العربية تلقائياً.
- الفواتير الآجلة الكبيرة (> 500,000) تُولّد إشعاراً للمدير.

## 💳 الديون والتسديدات
- تراكم آجل تلقائي في دفتر الذمم، مع كشف حساب زمني لكل مسحوباته.
- نافذة قبض: اختيار الزبون، المبلغ، التاريخ والوقت، طريقة الدفع (نقدي/تحويل/أخرى)، وملاحظة اختيارية.
- خصم فوري من الدين وإظهار المتبقي، وتوزيع تلقائي للمسددات على أقدم الفواتير (FIFO).
- **وصل قبض** عربي بمعاينة وطباعة A4 وحفظ PDF، برقم `ق-YYYY-#####` غير قابل للتكرار، مع إظهار الرصيد المتبقي.
- إشعار «تم تسديد الدين بالكامل» عند تصفير رصيد الزبون.
- إمكانية حذف وصل التسديد (للمدير) مع إعادة حساب الأرصدة والفواتير.

## 📊 التقارير والإحصائيات
خمسة تقارير، كلها بتاريخ من/إلى وتصدير بضغطة واحدة:
1. **حركة الصندوق** — النقدية اليومية (فواتير نقدية + تسديدات + دفعات مقدمة).
2. **الديون الشامل** — كل المدينين والمبالغ وإجمالي المطلوب في السوق.
3. **حركة مادة** — متى بيعت، لمن، الكميات المتبقية، الربح.
4. **الأرباح** — مبيعات، تكلفة، صافي ربح، هامش ربح.
5. **قيمة المخزون** — إجمالي القيمة، المواد المنخفضة والنافدة.

التصدير ملف **CSV بترميز UTF-8 مع BOM** وكل عناوينه عربية، يفتح مباشرة في إكسل أو جدول جوجل أو WPS على الهاتف، مع حماية من حقن الصيغ في الحقول النصية.

## 🔔 نظام الإشعارات
- **داخل التطبيق**: جرس مع عدّاد غير مقروء، وصفحة إشعارات بالتصفية، تحديد الكل كمقروء، وحذف.
- **خارج التطبيق**:
  - أندرويد: قناة إشعارات رسمية عبر Capacitor Local Notifications مع طلب إذن صريح.
  - ويندوز: إشعار نظام عبر Electron Notification API (والضغط عليه يُظهر النافذة).
  - المتصفح: Web Notifications عند توفر الإذن.
- أنواع التنبيهات: نفاد المخزون، فاتورة آجلة كبيرة، تصفير دين زبون، وإشعار تجريبي.
- منع تكرار التنبيه نفسه برمز ثابت (`code`)، ويزول تنبيه النفاد تلقائياً عند إعادة تعبئة المادة.

## 💾 النسخ الاحتياطي وأمان البيانات (القلب الوقائي)
- **تصدير يدوي**: ملف JSON واحد يحوي كل الجداول (بما فيها أرقام التسلسل وعلاماتها) باسم: `اسم_المكتب_نسخة_احتياطية_YYYY-MM-DD_HH-MM-SS.json`.
- **معاينة قبل الاستيراد**: اسم المكتب، تاريخ النسخة، وعدد سجلات كل جدول قبل أي كتابة.
- **فحص صارم قبل الكتابة**: بنية صحيحة + تطهير أنواع + تحقق من المراجع المالية والمخزنية + بصمة سلامة **SHA-256** لعدد السجلات، ثم استعادة **ذرية**.
- **نسخة أمان داخلية تلقائياً** قبيل أي استعادة، فيمكن التراجع.
- **نسخ داخلية دورية** داخل التطبيق (بدون تنزيل ملفات) حسب الإعداد: كل 30 دقيقة / ساعة / ساعتين / 6 ساعات / يومياً، ويُفحص الاستحقاق كل دقيقة (وأول فحص بعد 15 ثانية من الإقلاع)، وآخر 5 نسخ محفوظة للاستعادة بضغطة.
- **حفظ حسب المنصة**: أندرويد في `المستندات/إدارة المكتب/` ثم نافذة المشاركة؛ ويندوز بحوار حفظ أصلي؛ المتصفح في مجلد التنزيلات.
- منطقة خطر: حذف جميع البيانات مع **تأكيد نصي** وتنظيف كل الجداول.

## 🎨 الواجهة وتجربة الاستخدام
- لوحة تحكم بأزرار كبيرة: فاتورة بيع جديدة، إدخال مخزون، تسديد دين، إضافة مادة، الزبائن والديون — **وتظهر فقط ما تملك صلاحيته**.
- إحصاءات حيّة: مبيعات اليوم، إجمالي الديون، عدد المواد (مع منخفض/نافد)، عدد العملاء والفواتير، آخر الفواتير، أعلى المدينين، وقائمة المواد المنخفضة.
- تصميم عربي RTL بالكامل بلون هادئ (أخضر/ذهبي)، متجاوب على موبايل وتابلت وديسكتوب، ووضع ليلي كامل.
- اسم المكتب يظهر في الرئيسية ويُمرَّر تلقائياً إن تجاوز المساحة (ويتوقف عند مرور الفأرة).
- Layering للنوافذ (Modal Stack) مع إغلاق بـ Esc، وحوارات تأكيد عربية موحّدة، وتنبيهات Toaster.
- **حماية المسودات**: ما تكتبه في أي نموذج يُحفظ محلياً ويُستعاد بعد الرجوع أو إعادة التشغيل.
- **زر الرجوع الأصلي**: على أندرويد يُغلق النافذة أولاً ثم يرجع بين الشاشات، وتأكيد الخروج قبل إنهاء التطبيق، ولا يُنهى التطبيق أثناء الإقلاع أو الحفظ.
- **حاجز أخطاء** يمنع الشاشة السوداء: يعرض رسالة عربية وإعادة محاولة/تحميل بدل التجمد الصامت.
- PWA قابل للتثبيت مع أيقونات مخصّصة (وصل بختم «تم التسديد») وشاشة بدء عربية.

## 🪟 تكييفات سطح المكتب (Windows)
- مثبّت احترافي مع اختصار سطح المكتب وقائمة ابدأ، ونسخة محمولة بلا تثبيت.
- قائمة سياق عربية، تكبير/تصغير بـ Ctrl + عجلة الفأرة يُحفظ، أشرطة تمرير أعرض للفأرة، واستعادة موضع التمرير عند الرجوع.
- منع إفلات ملف فوق النافذة من استبدال الواجهة، ومنع تنقّل النافذة لمصادر خارجية.
- نسخة واحدة فقط تعمل (فتح التطبيق مرة أخرى يُظهر النافذة القائمة).
- بيانات الفواتير في مجلد ثابت لا تُحذف عند إلغاء التثبيت.

# 3) طريقة عمل التطبيق

## 3.1 رحلة الاستخدام اليومية

### أول تشغيل (مرة واحدة)
1. يُفتح التطبيق لأول مرة → يعرض **معالج التشغيل الأول**.
2. تُدخل بيانات المكتب الإلزامية: اسم المكتب، الهاتف، العملة، العنوان، تذييل الفاتورة (والشعار اختياري)، مع تحقق عربي فوري لكل حقل.
3. «حفظ وبدء استخدام النظام» → يُنشأ مدير واحد بلا رمز دخول معروف، وتبدأ الجلسة تلقائياً.

### الدخول والقفل (حسب الإعداد)
- مدير وحيد بلا رمز → دخول تلقائي مباشر بلا شاشة انتظار.
- إذا فُعّل رمز لأي حساب أو أُضيف أكثر من مستخدم → تظهر **شاشة الدخول**: اختر المستخدم → أدخل الرمز.
- 5 محاولات خاطئة → إيقاف مؤقت 30 ثانية مع عرض المدة المتبقية.
- نسيان رمز المدير → «نسيت الرمز؟» → إدخال رمز الاسترداد (12 رقماً) → تعيين رمز جديد.
- زر القفل في الشريط الجانبي يُنهي الجلسة ويبدّل المستخدم.

### إصدار فاتورة بيع (الاستخدام الأكثر تكراراً)
1. من لوحة التحكم: **فاتورة بيع جديدة** (أو الفواتير ← فاتورة جديدة).
2. اختر النوع: **نقدي** (زبون عابر مسموح) أو **آجل** (يجب اختيار زبون مسجل).
3. زبون آجل → يظهر دينه الحالي و«الرصيد السابق» الذي سيُطبع على الفاتورة.
4. أضف المواد: ابحث بالاسم → ينزل السعر تلقائياً → أدخل الكمية → يظهر إجمالي الصف فوراً (تحقق فوري من الكمية المتوفرة).
5. أدخل الخصم والمدفوع الآن (دفعة مقدمة) — النظام يقيد القيم ويمنع تجاوزها.
6. **حفظ** → تحديث ذري: خصم المخزون + قيد الذمة + رقم الفاتورة + تسجيل الدفعة المقدمة + فحص النفاد.
7. من صفحة الفاتورة: **معاينة / طباعة A4 / حفظ PDF / تعديل / حذف**.

### تسديد دين
1. من الرئيسية: **تسديد دين** (أو التسديدات ← تسديد جديد).
2. اختر الزبون → يظهر الدين الحالي والمتبقي بعد التسديد لحظياً.
3. أدخل المبلغ والتاريخ وطريقة الدفع (يظهر المتبقي بعد التسديد لحظياً).
4. **حفظ** → يُنشأ وصل قبض برقم فريد، يُقيَّد في دفتر الذمم، ويُعاد توزيع المسددات على الفواتير.
5. طباعة/معاينة الوصل أو حفظه PDF، والرصيد المتبقي مطبوع عليه.

### إدخال مخزون أو إضافة مادة
- **مادة جديدة**: المخزن ← إضافة مادة → الاسم/الوحدة/الكمية (والتكلفة الافتتاحية تُسجَّل كحركة) → حفظ.
- **إدخال مخزون**: زر «حركة مخزون» على المادة → كمية موجبة + تكلفة الوحدة + تاريخ + ملاحظة → يتحدث الرصيد و**متوسط التكلفة المرجّح** ذرياً.
- **تسوية نقص**: كمية سالبة مع سبب — ويرفض النظام أي حركة تجعل الرصيد سالباً.

### كشف حساب زبون
العملاء ← اختر الزبون → كشف زمني لكل الحركات (فواتير/تسديدات/خصومات) مع الرصيد الجاري → طباعة أو حفظ PDF أو تصدير للإرسال للزبون.

### التقارير
التقارير ← اختر التبويب (صندوق/ديون/حركة مادة/أرباح/مخزون) ← اضبط الفترة (زر «اليوم» أو «هذا الشهر» أو أي مدى مخصص بتاريخ من/إلى) → اقرأ الجدول والملخص → «تصدير التقرير» لحفظ ملف CSV عربي.

### النسخ الاحتياطي (روتين أسبوعي موصى به)
1. **تصدير الآن** → اختر مكان الحفظ (أندرويد: المستندات ثم مشاركة، ويندوز: حوار حفظ، متصفح: تنزيلات).
2. احتفظ بالملف على فلاش ميموري أو أرسله لنفسك — الملف يحوي كل شيء (بما فيه الإعدادات والمستخدمون وأرقام التسلسل).
3. للاسترجاع: **استيراد** → اختر الملف → راجع المعاينة (الاسم/التاريخ/عدد السجلات) → تأكيد → استعادة.
4. للتراجع السريع دون ملف: قائمة **النسخ الداخلية** ← «استعادة» بجانب النسخة المطلوبة.

### الإشعارات
اضغط الجرس لعرض الإشعارات، أو «تفعيل إشعارات النظام» لمنح الإذن وتجربة إشعار تجريبي. تصل التنبيهات أيضاً خارج التطبيق على أندرويد (شريط الإشعارات) وويندوز (مركز الإشعارات).

## 3.2 ما يحدث داخل التطبيق (شرح تقني)

### أ) تسلسل الإقلاع
```
checkStorageAvailable()  → وضع خاص/تخزين ممتلئ ⇒ شاشة عربية واضحة بدل شاشة بيضاء
initializeDB()           → فتح AgriOfficeDB وتشغيل ترقيات Dexie (v1→v3)
runStartupMaintenance()  → مصالحة الأرصدة وتحويل الرموز لبصمات (مرة واحدة) + قصّ السجلات (كل 24 ساعة)
setupAutoBackup()        → فحص كل دقيقة، وأول فحص بعد 15 ثانية؛ وينشئ نسخة داخلية عند الاستحقاق
initSystemNotifications()→ قناة أندرويد + أذونات ويندوز/المتصفح
isOfficeProfileComplete()→ ناقص ⇒ معالج أول تشغيل | كامل ⇒ tryAutoSignIn() أو شاشة الدخول
```
الحالة مرئية للمختبرات والأغلفة عبر `data-app-boot` (`loading` / `setup` / `ready`).

### ب) حفظ الفاتورة: كل شيء أو لا شيء
حفظ الفاتورة عملية واحدة داخل `db.transaction('rw', …)` على جداول: الفواتير، البنود، المواد، حركات المخزون، دفتر الذمم، التسديدات، سجل النشاط، الإشعارات، `meta`:
1. **تحقق كامل قبل أي كتابة** (زبون آجل مسجل، بنود غير فارغة، كميات موجبة، خصم ومدفوع ضمن الحدود).
2. **حساب المجاميع** بتقريب مالي آمن (كمية × سعر − خصم = الإجمالي).
3. **فحص توفر الكميات** لكل بند قبل الخصم — لا صرف لمادة غير متوفرة.
4. إسناد **رقم فاتورة فريد** من `nextInvoiceNumber` حسب تاريخ الفاتورة.
5. كتابة رأس الفاتورة وبنودها، وتثبيت تكلفة الوحدة وقت البيع (لأرباح دقيقة لاحقاً).
6. خصم الكميات وتسجيل حركات `sale` في المخزون.
7. للآجل: قيد موجب في **دفتر الذمم**؛ وللدفعة المقدمة: سجل تسديد بمصدر `downpayment` مع رقم وصل.
8. تسجيل نشاط + تنبيهات (فاتورة آجلة كبيرة/نفاد مخزون) — وأي فشل في الخطوات 1–7 يُلغي المعاملة كلها.
- **التعديل** يحسب فروق الكميات (delta) ويطبقها دفعة واحدة بدل الحذف والإرجاع؛ و**الحذف** يُرجع الكميات ويزيل قيود الذمة داخل المعاملة.

### ج) دفتر الذمم والأرصدة
- كل حركة مالية تُقيَّد في `customer_ledger` بمفتاح مركّب `[type+referenceId]` يمنع التكرار (نفس الفاتورة/الوصل لا تُقيَّد مرتين).
- رصيد الزبون = مجموع الحركات (موجب = دين، سالب = تسديد)، ويُحسب بمرور واحد على الجدول لكل الزبائن دفعة واحدة.
- بعد كل تسديد أو تعديل فاتورة: **إعادة توزيع المسددات** على الفواتير الآجلة من الأقدم للأحدث، فيتحدث `remaining` وحالة كل فاتورة (مدفوعة/جزئية/غير مدفوعة) — لكن الأرصدة نفسها تبقى محسوبة من الدفتر.
- «الرصيد السابق» في الفاتورة **لقطة ثابتة** عند الإنشاء ولا تدخل في `total` (كي لا تُحتسب مرتين)، لكنها تُطبع للزبون لتطابق حسابه.

### د) المخزون والتكلفة
- كل تغيير في الكمية يُسجَّل في `stock_movements` (نوع: `manual_entry` / `sale` / `adjustment`) بالتاريخ والتكلفة والمرجع.
- **متوسط التكلفة المرجّح**: `(الرصيد القديم × متوسطه + الكمية الداخلة × تكلفتها) ÷ الرصيد الجديد` — يُحدَّث ذرياً مع الإدخال.
- ربح البيع = (سعر البيع − تكلفة الوحدة المثبتة عند البيع) × الكمية.
- منع الرصيد السالب في كل المسارات، وإعادة حساب الحالة (منخفض/نافد) وإدارة تنبيهات النفاد.

### هـ) ترقيم المستندات
- **الفاتورة**: `ف-YYYYMM-NNNN`، **الوصل**: `ق-YYYY-#####`.
- المنطق: أعلى رقم موجود في الجدول ∪ علامة high-water في `meta` (تُحدَّث ولا تتراجع)، ثم التحقق من عدم استخدام الرقم؛ إن تراجعت معاملة، يُفقد الرقم ولا يُعاد استخدامه.
- البادئات القديمة (INV/REC) تُحتسب ضمن نفس التسلسل وتُعرض بالبادئة العربية، فلا تتكرر الأرقام ولا تختلط.

### و) النسخ الاحتياطي والاستعادة
- **التصدير**: قراءة كل الجداول + عدّها + حساب بصمة SHA-256 لمحتوى السجلات + كتابة ملف JSON عبر خدمة الحفظ الموحّدة (Filesystem/share على أندرويد، حوار أصلي على ويندوز، تنزيل على المتصفح).
- **الاستيراد على مرحلتين**: (1) قراءة بحد أقصى للحجم → فحص البنية والأنواع والمراجع والحصيلة → عرض معاينة؛ (2) بعد تأكيد المستخدم: أخذ نسخة أمان داخلية ثم استبدال كل الجداول ذرياً.
- **الحفظ التلقائي** ينشئ نسخاً داخلية (snapshots) بتوقيع يمنع التكرار، ويبقي آخر 5، مع تنظيف القديم.
- أرقام التسلسل (`مفاتيح seq:`) جزء من النسخة، فلا يُعاد استخدام رقم محذوف بعد الاستعادة على جهاز جديد.

### ز) الطباعة والمعاينة و PDF
- **هندسة ورقة واحدة** (A4: 210×297 مم بهامش 10 مم) تُستخدم في المعاينة والطباعة و PDF، فتتطابق الأعمدة والفواصل والالتفافات في المخرجات الثلاثة.
- الطباعة عبر **iframe** لا `window.open` (النوافذ المنبثقة محجوبة في WebView و Electron)، ولا يُعلن النجاح إلا بعد حدث `beforeprint` حقيقي.
- كل قيمة نصية تُهرَّب (`escapeHtml`) قبل إدراجها في مستند الطباعة لمنع XSS من أسماء أو ملاحظات مستوردة.
- jsPDF و html2canvas يُحمَّلان **تأخيرياً** عند حفظ مستند فقط، فلا يثقلان إقلاع التطبيق.

### ح) الإشعارات
- تُخزَّن في قاعدة البيانات (داخل التطبيق) وتُرسَل خارجياً حسب المنصة: قناة أندرويد رسمية بأهمية عالية واهتزاز، إشعار Electron، أو Web Notification.
- **منع التكرار** برمز `code` + الكيان المرتبط، ويزول التنبيه عند زوال سببه.
- فشل الإشعارات لا يؤثر على العملية الأصلية (يُسجَّل فقط).

### ط) الصيانة عند البدء (مرة يومياً أو مرة واحدة)
- **مصالحة الأرصدة** (`allocation-v1`): إعادة توزيع كل المسددات على الفواتير الآجلة مرة واحدة لتصحيح أي بيانات قديمة.
- **تحويل الرموز النصية القديمة** إلى بصمات SHA-256 عند أول تشغيل (`pin-hash-v1`).
- **قصّ السجلات**: إبقاء آخر 500 سجل نشاط و300 إشعار حتى لا تتضخم القاعدة مع السنين.

### ي) الصلاحيات ودورة الحياة
- `Role → Permission` مصفوفة واحدة: القائمة الجانبية و RouteGuard وزر الواجهة، ثم `assertPermission` داخل دوال الحفظ/الحذف (دفاع ثانٍ). فشل الصلاحية يُعرض برسالة عربية موحّدة.
- الجلسة **في الذاكرة فقط**: إعادة التشغيل تتطلب دخولاً جديداً عند تفعيل القفل (كسلوك تطبيقات نقاط البيع)، والمهام الخلفية تعمل بلا جلسة.
- زر الرجوع على أندرويد يمرّ بمكدس النوافذ ثم سجل التنقل، ثم حوار تأكيد الخروج — ولا يُسمح بإنهاء التطبيق أثناء الإقلاع أو عمليات الحفظ.

```bash
git clone https://github.com/techtouchAI/Debt-register.git
```

# 5) الأمان والخصوصية

- **100% دون إنترنت**: لا API، لا تحليلات، لا Firebase، ولا أي طلب شبكة من التطبيق.
- **البيانات محلية**: IndexedDB داخل الجهاز، مع طلب تخزين دائم من النظام حتى لا تُحذف تلقائياً عند امتلاء المساحة.
- **رموز الدخول**: بصمة SHA-256 مملّحة فقط، ولا تُعرض ولا تُطبع ولا تُصدَّر كنص صريح، مع قفل مؤقت بعد المحاولات الخاطئة.
- **استيراد آمن**: أي ملف نسخة يمرّ بفحص بنية وأنواع ومراجع وبصمة سلامة قبل الكتابة، والاستعادة ذرية مع نسخة أمان تلقائية.
- **طباعة آمنة**: تهريب كامل لكل قيمة مُدخلة قبل إدراجها في مستندات الطباعة (منع XSS مخزّن).
- **تصدير آمن**: حماية ملفات CSV من حقن الصيغ، والملفات النصية BOM عربي.
- **Electron محصّن**: عزل السياق مُفعّل، `sandbox` مُفعّل، `nodeIntegration` معطّل، منع التنقل لمصادر خارجية، جسر IPC محروس، ونسخة واحدة.
- **PWA**: يعمل دون إنترنت بعد أول تحميل، وService Worker لا يُسجَّل داخل أغلفة Capacitor/Electron/Tauri.

# 6) حل المشكلات الشائعة

| المشكلة | السبب والحل |
|---|---|
| ومضة ثم شاشة سوداء (نسخة قديمة) | أُصلح بالانتقال إلى `HashRouter` ومسارات نسبية؛ حدّث التطبيق ثم «مسح ذاكرة التخزين المؤقت وإعادة التحميل» من شاشة الخطأ |
| شاشة «حدث خطأ غير متوقع» | حاجز الأخطاء الجديد؛ اضغط إعادة المحاولة — بياناتك في IndexedDB سليمة |
| «تعذّر فتح قاعدة البيانات المحلية» | وضع تصفح خاص أو مساحة ممتلئة؛ استخدم نافذة عادية، واسمح بالتخزين، وفرّغ مساحة |
| الطباعة لا تظهر شيئاً | بعض البيئات تُهمل `print()` صامتاً؛ استخدم **حفظ PDF** ثم اطبعه، أو تأكد من السماح بطباعة الإطارات |
| لا تصل إشعارات النظام | فعّلها من صفحة الإشعارات، وامنح الإذن من إعدادات النظام، ثم أرسل إشعاراً تجريبياً |
| نسيت رمز الدخول | استخدم رمز الاسترداد (12 رقماً) من شاشة الدخول لتعيين رمز جديد |
| فقدت بيانات بالخطأ | النسخ الاحتياطي ← النسخ الداخلية ← استعادة النسخة الأقرب زمنياً، أو استيراد ملف JSON |
